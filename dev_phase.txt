### Phases of Development

**Phase 1: Environment Setup & Smart Contract Foundation (Layer 3)**

* Initialize the Hardhat/Foundry project using Polygon testnet (or chosen EVM/L2 network).


* Implement `DetectionAuditTrail.sol` to record detection events, cryptographic audio hashes, caller identities, spoof probabilities, and timestamps.


* Set up `VoiceRegistry.sol` to store hashed voice embeddings mapped to Decentralized Identifiers (DIDs) without exposing raw biometric data.


* Deploy contracts to the testnet, verify deployment, and integrate `IPFS` helpers for off-chain hash referencing.



**Phase 2: AI Detection & Verification Engine Setup (Layer 1)**

* Set up inference scripts using fine-tuned Wav2Vec2 or RawNet2 for deepfake/spoof probability scoring.


* Build the feature extraction pipeline: compute Mel-spectrogram irregularities, pitch contours (F0), prosody micro-pauses, and neural vocoder artifacts.


* Integrate a secondary speaker verification check using SpeechBrain (ECAPA-TDNN) to match voice embeddings against enrolled voiceprints.


* Build a 2–4 second sliding-window chunk processor (`inference_stream.py`) to prepare for live, sub-second streaming inference.



**Phase 3: Prevention Pipeline & Risk Engine Integration (Layer 2)**

* Build a FastAPI backend with a WebSocket/WebRTC endpoint to ingest raw audio chunks continuously.


* Implement the multi-factor `risk_engine.py`: combine AI spoof confidence with contextual parameters (e.g., mismatch threshold, call metadata).


* Create trigger thresholds:


* *Low Risk:* Normal processing.


* *Medium Risk:* Warning flag and interactive challenge question.


* *High Risk:* Call block/flag and transaction auto-freeze signal.




* Wire the backend to automatically dispatch transaction transactions to `DetectionAuditTrail.sol` when an audio chunk is flagged.



**Phase 4: Dashboard UI & Live Interception Demo (Frontend)**

* Build the React dashboard with live audio streaming/file-upload controls.


* Implement real-time risk status indicators displaying the spoof probability score and the corresponding action banner (Low/Medium/High).


* Integrate an explainability visualization component rendering Mel-spectrogram heatmaps highlighting anomalous frequency-time bins.


* Build the audit log table pulling verified event transactions directly from the deployed smart contract.



**Phase 5: End-to-End Testing & Hackathon Demo Rehearsal**

* Run end-to-end trials using test sets of authentic voices alongside synthetic samples (ElevenLabs, Tortoise, or RVC).


* Ensure streaming latency stays within real-time bounds for short 2–4 second window chunks.


* Validate that high-risk flagged calls immediately trigger a confirmed immutable log entry on the blockchain explorer.
